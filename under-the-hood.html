Under the hood.

For the curious: what the apps touch, how a backup is checked, and how everything stays on your computer.

What it touches

Backups reads your projects. It never edits them.

Reads

  • The project folders you add in Setup
  • The sample libraries you point it at, to find missing sounds
  • Your exports folder, to link songs to projects

Writes

  • Dated snapshots on the backup drive or NAS you choose
  • Its own history folder (see where your data lives)
  • A restored copy, only into a folder you pick

Never

  • Modifies, moves or deletes your original projects or samples
  • Uploads your audio anywhere you didn't set up yourself
  • Sends your project names, file list or music to us

Uploader reads the bounce folders you choose and sends audio straight from your computer to your own SoundCloud account. It edits or deletes a SoundCloud track only when you click to do so.

How a backup works

Copied once, checked twice.

Follows every sample
Each project file is read to find the samples it uses, wherever they live. Supported: Ableton Live, FL Studio, Reaper, Audacity and DAWproject files.
No duplicate copies
Every file gets a fingerprint (SHA-256) of its contents. A sample used by twenty projects is stored once on the backup drive, so snapshots stay small.
Checked as it's written
The fingerprint is taken from the bytes that actually landed on the drive, so a file that changed mid-copy is never kept.
Verified afterwards
Each snapshot has a list of every file with its size and fingerprint. Verifying re-reads every file and compares, which catches a half-written file or a failing drive, and checks the backed-up project finds all its samples inside the backup.
Moved samples
When a sample has moved, Backups relinks it inside the backup copy, matched by file size and not just its name. The project on your computer is left exactly as it was.

How Uploader works

Never the same mix twice.

Spots repeats
Each mix is fingerprinted (SHA-256) from the audio file itself, not its name. Renaming a file doesn't fool it; re-rendering with a change counts as a new mix.
Knows the source
With Backups installed, Uploader reads Backups' records on your computer to show each mix's project, tempo and genre.
SoundCloud sign-in
Signing in passes through a small Lazy Creatives service that holds our SoundCloud app secret. It only swaps the sign-in code for your access keys and keeps nothing.
Your login, locked away
Your SoundCloud keys are stored encrypted on your computer: with Windows' own user-account protection, the macOS Keychain, or the Linux keyring. On a Linux desktop with no keyring, the key goes in a file only your user can read.

How it runs

Everything happens on your computer.

Two parts
The window you see is a desktop app (built with Electron). The work is done by a small engine written in Python that starts and stops with it.
Local only
The two talk over 127.0.0.1, an address only reachable from your own computer, never from your network or the internet.
Locked to the app
Each time the app starts it makes a fresh secret key, and the engine refuses any request without it. Other programs and web pages can't drive it.
Updates
When it opens, each app checks its own official Releases page (Backups, Uploader) and nowhere else. On Windows and Linux it downloads the update in the background and asks before restarting the app; choose "Later" and it installs next time you quit. On a Mac it shows a button to the download page.
Builds
Installers for all three systems are built automatically on GitHub for each release, and published with their fingerprints. What changed in each one is on What's changed.

Where your data lives

On your computer, in one folder per app.

Backups history
%LOCALAPPDATA%\ablebackup on Windows, ~/.ablebackup on Mac and Linux
Your backups
On the drive or NAS you chose, as dated snapshot folders you can open without the app
Source code
Published on GitHub, so anyone can read exactly what the apps do. See the licence for what you may do with it.
